# ライブコーディング台本 — `労働時間帯分割` を Souther で書く

対象は元の Java クラス [`domain/追加業務検知/労働時間帯分割.java`](../../../src/main/java/com/example/Backend/domain/追加業務検知/労働時間帯分割.java)（`main` ブランチ）と、そこから呼ばれる `specification/*ルール.java` 7 つです。範囲は「報告 1 件の労働時間帯を分割する」部分に絞ります。リストを回す for 文や、結果の record への詰め替えは扱いません。

各ステップの「緑」の状態を `step1-型/` 〜 `step6-講義前にはみ出し/` に置きました。どれも souther 0.5.0 でコンパイルが通ることを確認済みです。打ち間違えて戻れなくなったら、該当ステップのファイルをコピーして続けます。

---

## 0. 方針

### 「まず .sou を作り、example を 1 つずつ解決する」流れは Souther に合っているか

**合っています。** ただし、普通の TDD と違う点が 2 つあり、そこを見せるのがこのライブの山場です。

1. **最初に作るのは「型」。** Java 版の不具合 3 件（長さ 0 の時間帯、開始と終了の逆転、曜日の表記ゆれ）は、example ではなく型（invariant と sum）で消えます。.sou の最初の数分は、`let` も example も書かずに `data` を書きます。
2. **2 本目以降の example は、人ではなくレポートが決める。** 業務の代表例（Java の分岐 4.1〜4.4）は人が手で書きます。それ以降は `souther examples` の `!`（不足）が「次に書くべき行」を教えてくれます。分岐網羅が 100% でも、境界の 1 秒内側や曜日の網羅が足りないと指摘されます。

あわせて、Souther には example を先に書くための仕組みがそろっています。

- `let` がない behavior に書いた example は、エラーにならず「保留」として記録されます。`let` を書いた時点から評価されます。
- 期待値を `<?>` にした行も書けます。`--generate` は、足りない行を `<?>` 付きで出力します。

「赤」は example の失敗（E1905）だけではありません。次のコンパイルエラーも赤として扱い、それぞれをライブの見せ場にします。

| コード | 内容 |
|---|---|
| E1903 | 不正な入力が作れない |
| E1002 / E1006 | `constructs` の宣言と実装が合わない |
| E2010 | invariant 違反を、example なしでコンパイル時に検出 |

### なぜこのクラスを選ぶか

| 候補 | 判断 |
|---|---|
| **`労働時間帯分割`** | **採用。** null 許容の 4 フィールドで結果を表しており、7 つのルールを if で入れ子にしています。Souther の sum・invariant・guard・境界レポートのすべてに効き目があります。Java 版の不具合も実測済みです。 |
| `カレンダー` | 日付から曜日を求めるだけで、Souther で書いても見せどころが少ない。 |
| `specification/*ルール` 単体 | boolean を返す述語にすぎない。Souther は結果を sum で表す設計なので、1 つだけ取り出すと良さが出ない。 |
| `労働情報表示` など | 表示・I/O が中心で、Souther の対象外。 |

## 1. 準備

```bash
mkdir live && cd live
touch 労働時間帯分割.sou 労働時間帯分割.examples.sou
alias sc='souther compile --lang ja -d /tmp/out 労働時間帯分割.sou 労働時間帯分割.examples.sou'
alias se='souther examples --lang ja 労働時間帯分割.sou 労働時間帯分割.examples.sou'
```

- 画面は左にエディタ、右にターミナルを置きます。
- `--lang ja` を付けると、エラーとレポートが日本語になります（0.5.0 から）。
- **注意: example が 1 行もない状態で `se` を実行すると、souther 0.5.0 は内部エラーになります。** step2 より前は `sc` だけを使います。
- 比較用に、Java の `労働時間帯分割.java` を別のタブで開いておきます。

## 2. 手順

時間は目安です。★ はそのステップの見せ場です。

### step1 型（3 分）→ [`step1-型/`](step1-型/)

`曜日`（7 つの case の sum）、`時間帯`（`invariant 開始は終了より前`）、`講義情報` を書きます。

- 対比として話すこと: Java は `講義の曜日(String)` で、`"水曜"` も通ります。`時間帯` は開始 ≥ 終了でも作れます。
- `sc` を実行すると何も出ずに通ります。

### step2 結果の型・behavior の宣言・最初の example（4 分）→ [`step2-宣言と最初のexample/`](step2-宣言と最初のexample/)

1. 結果の型を書きます。Java の「null 許容の 4 フィールド（16 通り）」を、まずは 2 つの case の sum `講義のない曜日の労働 | 講義時間内の労働` で表します。
2. `behavior 労働時間帯を分割する : (講義, 労働, 労働の曜日) -> 労働時間帯の区分` を宣言します。`let`（実装）はまだ書きません。
3. examples ファイルに、Java 4.1「講義のない曜日は全て追加労働」の行を 1 つ書きます。
4. `sc` が通り、`se` では「注入 / 保留 1」と表示されます。★ **実装より先に仕様を書いておける。**
5. ★ **Java 版の不具合入力を 1 行足してみせます**（長さ 0 の 10:40〜10:40）。
   - E1903「入力 #2 を構築できない: invariant 違反」になります。
   - 確認したら、その行は消します。

### step3 仮実装（3 分）→ [`step3-仮実装/`](step3-仮実装/)

1. `let` で常に `講義のない曜日の労働 { 追加労働時間帯 = 労働 }` を返し、`constructs` には `講義のない曜日の労働` だけを書きます。最初の行が通り、緑になります（いわゆる仮実装）。
2. Java 4.2「講義時間内は全て通常労働」の行を足すと、**E1905** で赤になります。
   - エラーには「行は 講義時間内の労働 と書いていますが、behavior は 講義のない曜日の労働 を返しました」と、期待と実際が並んで出ます。

### step4 曜日の判定（3 分）→ [`step4-曜日の判定/`](step4-曜日の判定/)

1. `guard 労働の曜日 == 講義.講義の曜日 else 講義のない曜日の労働 {...}` と、最後に `講義時間内の労働 {...}` を書きます。
2. ★ `sc` を実行すると **E1002** が出ます。「講義時間内の労働 を構築していますが constructs を宣言していません」。
   - この behavior が何を作るかを、宣言と実装の両方からコンパイラが突き合わせています。
   - ヒントに従って `constructs` に追加すると、緑になります。
3. 対比として話すこと: Java の `曜日が一致するかルール` クラス（21 行）が、guard 1 行になりました。

### step5 講義時間外（5 分）→ [`step5-講義時間外/`](step5-講義時間外/)

1. sum に `講義時間外の労働` を足し、「講義の前に終わった（9:00〜10:00）」の行を書きます。
   - `constructs` にはまだ足しません。先に足すと、E1006「宣言したのに構築していない」になります。
2. **E1905** になります（実際は 講義時間内の労働）。
3. 重なりの判定 `guard 労働.終了 > 講義時間.開始 && 労働.開始 < 講義時間.終了 else 講義時間外の労働 {...}` を書き、`constructs` に追加して緑にします。
4. 境界の行「講義の開始ちょうど（10:40）に終わった」を足しても緑のままです。
5. 対比として話すこと: Java の `講義時間以外で労働しているルール` は「より早い、または同じ」を `isBefore || equals` で書いていました。

### step6 講義前にはみ出し ＝ 複数のフィールドにまたがる invariant（5 分）→ [`step6-講義前にはみ出し/`](step6-講義前にはみ出し/)

1. `data 講義前にはみ出した労働 = { 前の追加労働時間帯, 通常労働時間帯 } invariant 隙間なく続く = 前の追加労働時間帯.終了 == 通常労働時間帯.開始` を書きます。
2. 「講義の前から途中まで（10:00〜11:00）」の行を足すと、**E1905** になります。
3. `if 労働.開始 < 講義時間.開始 then 講義前にはみ出した労働 {...} else 講義時間内の労働 {...}` を書きます。
4. ★ **わざと間違えます。** 通常労働時間帯の開始を `労働.開始` にすると、**E2010** になります。
   - 「この経路でこの値を構築すると `隙間なく続く` に違反する」というエラーです。
   - **example の値とは関係なく**、分岐条件から違反を導いて止めています。
   - 正しく `講義時間.開始` に直し、`constructs` に `時間帯` と `講義前にはみ出した労働` を追加して緑にします。

### step7 レポートに次の example を決めさせる（5 分、時間に応じて伸縮）

1. `se` を実行すると、分岐 6/6・置き換え 6/6 なのに **`!` 不足 26 件、十分性: 未充足** と出ます。
2. ★ 指摘を読み上げます。
   - 「`月` を使うテストケースがない」: 曜日の網羅が足りない。
   - 「ON 点（comparison@28:17）にテストケースがない」: 1 秒単位の境界が足りない。
   - Time は秒まで持つので、`>` と `>=` の取り違えを見分けるには「10:40:01 に終わった」行が要る、と説明します。
3. 「開始の 1 秒後に終わった（10:00〜10:40:01）」の行を、期待値を考えながら手で書きます。不足が 1 件減ります。
4. `souther examples --generate --lang ja ...` を見せます。
   - 残りの不足を埋める行が、期待値 `<?>` の状態で出てきます。
   - 入力値は機械的です（00:00:00〜00:00:01 など）。**どの入力で確かめるかはツールが決め、何が正しいかは人が決める**、という分担を示します。
5. ここで、完成版（[`src/main/souther/追加業務検知.sou`](../../../src/main/souther/追加業務検知.sou)）に切り替えます。
   - `souther examples --strict` を実行すると、不足 0 件・終了コード 0 で通ることを見せて締めます。
   - 残りの 2 つの case（講義後 / 前後にはみ出し）は、step6 と同じパターンなので省略します。

## 3. 想定される結果

| 時点 | example の行数 | 状態 |
|---|---|---|
| step2 | 1 | 注入・保留 1。コンパイルは通る |
| step6 | 5 | 分岐 6/6、同値分割 3/14、境界 8/17、**`!` 26 件** |
| 完成版（2 つの case を追加） | 23（分割のみ） | 同値分割 14/14、境界 25/25、**`!` 0 件**、`--strict` 終了コード 0 |

伝わるはずのこと:

- Java 版の不具合 3 件は、型を書いた時点（step1〜2）で入力として作れなくなる。
- コンパイラが止めるのは、テストの失敗だけではない。
  - `constructs` の過不足（E1002 / E1006）
  - invariant 違反を経路から導いたもの（E2010）
  - 不正な入力（E1903）
- 分岐網羅 100% は「十分」ではない。次に書くべき example をレポートが具体的な値で示す。

## 4. 予備知識・リスク

- コンパイルは毎回 1〜2 秒かかります。待ち時間は、Java との対比を話してつなぎます。
- エラーメッセージが長いので、ターミナルの文字は大きめにして、`| head -20` で切る運用も考えます。
- 構文で詰まったら、該当する `stepN/` のファイルをコピーして先に進みます。
- 本番でも `--lang ja` を使います。英語のほうが会場に合う場合は外します。
